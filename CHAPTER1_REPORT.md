## 1.3. Архитектура современных веб-приложений: клиент-серверное взаимодействие и REST-интерфейсы

Для реализации современной образовательной платформы наиболее целесообразным является использование многоуровневой архитектуры, основанной на принципе разделения ответственности (Separation of Concerns).

**Эволюция веб-архитектуры: от монолита к SPA.** В SPA-приложении (Single Page Application) клиентская часть загружается один раз, а последующее взаимодействие с сервером происходит в фоновом режиме через API. Это обеспечивает:
*   Отсутствие перезагрузок страницы при навигации.
*   Снижение нагрузки на сервер.
*   Возможность разработки независимых мобильных приложений на базе одного и того же API.

**Архитектурный стиль REST.** В основе взаимодействия лежит REST (Representational State Transfer). Ключевые принципы:
1.  **Client-Server:** Разделение UI и хранения данных.
2.  **Stateless:** Сервер не хранит сессии клиента. Каждому запросу должны быть предоставлены все необходимые данные (например, токен авторизации).
3.  **Cacheability:** Ответы сервера могут помечаться как кешируемые для повышения скорости.

*Таблица 3 — Сравнение архитектурных подходов*

| Критерий | Monolith (MPA) | Distributed (SPA + API) |
| :--- | :--- | :--- |
| **Рендеринг** | На стороне сервера | На стороне клиента (Browser) |
| **Связанность** | Высокая (Код UI и логики перемешан) | Низкая (Раздельные репозитории) |
| **Масштабируемость** | Затруднительна | Высокая (Горизонтальное масштабирование) |
| **UX** | Частые перезагрузки | Плавные переходы |

## 1.4. Характеристика протоколов безопасности и механизмов аутентификации

Безопасность платформы «NEO STUDY» базируется на современных стандартах защиты данных.

**Аутентификация на основе JWT (JSON Web Token).** JWT — это компактный, безопасный для URL способ представления претензий (claims) для передачи между двумя сторонами. Токен состоит из:
*   **Header:** Тип токена и алгоритм подписи (например, HS256).
*   **Payload:** Полезная нагрузка (ID пользователя, роль, срок действия).
*   **Signature:** Криптографическая подпись, созданная с использованием секретного ключа сервера.

**Безопасность согласно OWASP Top 10.** При проектировании системы учитывались следующие угрозы:
1.  **Injection:** Защита от SQL-инъекций обеспечивается использованием ORM SQLAlchemy.
2.  **Broken Authentication:** Использование надежных алгоритмов хеширования паролей (bcrypt/pbkdf2).
3.  **Sensitive Data Exposure:** Использование протокола HTTPS для шифрования трафика.
4.  **XSS (Cross-Site Scripting):** React автоматически экранирует данные, предотвращая вставку вредоносных скриптов в интерфейс.

## 1.5. Обзор технологий разработки фронтенд-части: библиотека React 19 и принципы компонентного подхода

Фронтенд реализован на базе React 19. Ключевой особенностью этой версии является улучшенная работа с серверными компонентами и оптимизация хуков.

**Virtual DOM и Reconciliation.** React создает виртуальное дерево DOM в памяти. При изменении состояния вычисляется минимальное количество изменений, которые нужно применить к реальному DOM. Это избавляет от необходимости перерисовывать всю страницу при изменении одного счетчика или текста.

**Управление состоянием (State Management).** В проекте используются:
*   **useState:** Локальное состояние компонента.
*   **useEffect:** Синхронизация с внешними системами (API).
*   **Context API:** Глобальное состояние (данные авторизованного пользователя), доступное любому компоненту без передачи через пропсы.

**Декларативный подход.** В отличие от императивного программирования (где мы говорим браузеру "найди кнопку и поменяй ей цвет"), в React мы описываем, как интерфейс должен выглядеть в зависимости от данных. Это делает код более предсказуемым и легким в тестировании.

## 1.6. Роль типизации в современной веб-разработке: язык TypeScript

TypeScript является надмножеством JavaScript, которое добавляет статическую типизацию.

**Основные концепции TypeScript в проекте:**
*   **Interfaces:** Описание структуры объектов. Например, интерфейс `ITask` гарантирует, что у каждой задачи будет `id`, `title` и `question`.
*   **Generics:** Обобщенные типы, позволяющие создавать переиспользуемые компоненты (например, универсальный компонент таблицы).
*   **Enums:** Перечисления для ролей пользователей (ADMIN, STUDENT).

Использование TypeScript сокращает количество ошибок в рантайме на 15-20%, что критически важно для образовательного продукта, где точность данных приоритетна.

## 1.7. Характеристика серверных технологий: микрофреймворк Flask и экосистема Python

Flask — это WSGI-микрофреймворк, написанный на языке Python. Его называют микрофреймворком, потому что он не требует специальных инструментов или библиотек.

**Преимущества для проекта:**
1.  **Легкость:** Отсутствие лишнего функционала "из коробки" позволяет держать кодовую базу чистой.
2.  **Экосистема расширений:** Flask-SQLAlchemy для БД, Flask-JWT-Extended для авторизации, Flask-CORS для настройки доступа.
3.  **Интеграция с ML/AI:** Поскольку Yandex GPT и другие модели имеют нативные Python SDK, Flask становится идеальным связующим звеном.

## 1.8. Управление данными и ORM-системы: SQLAlchemy и Alembic

**SQLAlchemy** реализует два паттерна: Core (SQL-выражения) и ORM (Object-Relational Mapping). В проекте используется ORM для работы с объектами.

*Пример структуры данных (ER-модель):*
*   **User:** id, username, password_hash, role.
*   **Task:** id, number, title, question, answer.
*   **SolvedTask:** user_id, task_id, solved_at (связь "многие ко многим" между пользователями и задачами).

**Alembic** управляет эволюцией базы данных. Каждая миграция — это шаг вперед или назад в истории схемы БД. Это позволяет команде разработчиков синхронизировать структуру таблиц без потери данных.

## 1.9. Технологии визуализации математического контента: LaTeX и KaTeX

Для отображения формул используется **KaTeX**. Это библиотека, которая парсит строки в формате LaTeX и превращает их в визуально корректные формулы.

**Почему не MathJax?**
*   MathJax загружается дольше и рендерит формулы асинхронно, что вызывает "прыжки" контента.
*   KaTeX рендерит формулы мгновенно и имеет меньший размер бандла.
*   Поддержка в React через компоненты (например, `react-katex`) позволяет динамически обновлять формулы при получении данных от ИИ.

## 1.10. Роль и принципы функционирования больших языковых моделей (LLM) в образовании

**Архитектура Transformer.** Модели типа GPT основаны на механизме внимания (Attention). Модель вычисляет веса связей между словами. Например, в предложении "В треугольнике ABC угол A равен 30 градусам" модель понимает, что "30 градусов" относится к "углу A", а не к "треугольнику".

## 1.13. Методы кластеризации и классификации в анализе образовательных данных (EDM)

**Алгоритм K-Means (К-средних).** Метод разделения набора данных на $k$ заранее известных кластеров. В образовании используется для сегментации учеников по вектору признаков: $[точность, скорость, активность]$.
$$J = \sum_{i=1}^{k} \sum_{x \in S_i} ||x - \mu_i||^2$$
Где $\mu_i$ — центр кластера (центроид).

**Деревья решений (Decision Trees).** Могут использоваться для предсказания вероятности успешной сдачи экзамена на основе текущих успехов по разным темам.

## 1.14. Технологии контейнеризации и развертывания: Docker и CI/CD

**Docker** позволяет изолировать приложение. Файл `Dockerfile` описывает все слои: от базовой ОС (Alpine Linux) до установки зависимостей `pip install`.
`docker-compose.yml` координирует работу двух сервисов: фронтенда (Vite/React) и бэкенда (Flask/Gunicorn).

**Преимущества:**
*   **Consistency:** "Работает у меня — работает везде".
*   **Security:** Ограничение прав доступа процесса внутри контейнера.
*   **Version Control:** Образы контейнеров можно версионировать в Docker Registry.

## 1.16. Резюме по первой главе

Первая глава посвящена теоретическому обоснованию выбора технологий и методологий. Установлено, что связка React 19 + Flask является оптимальной для создания гибкой и производительной платформы. Интеграция LLM (Yandex GPT) и использование методов анализа данных (K-Means) позволяют создать адаптивную образовательную среду, способную эффективно готовить учащихся к профильному экзамену по математике в условиях цифровой трансформации.
